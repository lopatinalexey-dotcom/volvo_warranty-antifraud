# Платформа автоматизированного риск-скоринга и антифрод-аудита дилерской сети (на примере Volvo Car Russia)

### 📌 Обзор проекта
Данный пет-проект представляет собой реляционную базу данных промышленного масштаба (на базе СУБД MySQL), моделирующую транзакционную активность ремзоны официальных дилерских центров (60 000 уникальных автомобилей, 100k+ заказ-нарядов, 400k+ строк спецификаций). 

Цель проекта — математическое выявление скрытых схем дилерского фрода, процедурных нарушений, клиентского экстремизма, а также превентивный мониторинг критических юридических рисков для Импортера по ЗОЗПП. База данных содержит 35% скрытых искажений (приписки нормо-часов, избыточное списание запчастей, повторные ремонты), которые выявляются исключительно методами перекрестных SQL-запросов к эталонному справочнику нормативов.

---

### 📑 Стратегический антифрод-отчет для топ-менеджмента

#### БЛОК 1. Юридический рекомендательный анализ (Риски ЗОЗПП и «Проклятые ведра»)
* **Бизнес-проблема:** Автомобили премиум-сегмента (XC90, XC70, S80) с безлимитной двухлетней гарантией накапливают критические дни нахождения в ремонте или повторно возвращаются с одним и тем же неустраненным CSC-кодом дефекта (Customer Symptom Code). Дилеры на местах часто маскируют эти случаи в закрытых нарядах, скрывая задержки поставок дефицитных деталей (Back-Order) или низкую квалификацию диагностов цеха. Это подставляет Импортера под прямые судебные иски о возврате полной стоимости машины по Закону о защите прав потребителей.
* **Методология выявления:** SQL-скрипты перекрестно анализируют таймлайны открытия/закрытия нарядов по уникальным VIN-кодам, сопоставляют их с платформенной применяемостью агрегатов и группируют по повторяющимся кодам рекламаций. Алгоритм вычисляет «проклятые ведра» на ранней стадии — до того, как клиент нанимает адвоката.
* **Экономический эффект:** Внедрение автоматического триггера «Раннее предупреждение ЗОЗПП». При фиксации 2-го повторного визита по критическому узлу система автоматически передает VIN в департамент клиентского сервиса Импортера. Это позволяет превентивно перехватить клиента, выделить подменный автомобиль и направить технического тренера для принудительного решения проблемы. Предотвращение судебных выплат обеспечивает прямую экономию от **3.5 до 7+ млн рублей** с каждого удержанного от суда автомобиля, защищая репутацию бренда.

#### БЛОК 2. Аудит финансовых утечек комплаенса (VSTG Padding & Part Padding)
* **Бизнес-проблема:** Искусственное раздувание дилерами стоимости гарантийного требования (клейма), выставляемого Импортеру на оплату. Операторы дилеров умышленно завышают нормативы времени (VSTG — Volvo Standard Times Guide), приписывая лишние десятые доли нормо-часа (например, вместо эталонных 0.9 Н/Ч на замену задней ступицы XC90 вбивают 1.3 или 1.4 Н/Ч). В дорогих ремонтах агрегатов (ДВС D5, роботы PowerShift на S40), требующих одобрения со стороны руководства представительства (Мистер Фёрст, Мистер Секонд, Миссис Тилберн), дилеры скрытно дописывают избыточные сопутствующие детали (оригинальные турбины, избыточный крепеж), пользуясь тем, что VIP-согласования проверяются инженерами «на потоке».
* **Методология выявления:** SQL-запросы выполняют жесткую математическую сверку каждой позиции «Работа» с эталонной матрицей VSTG по конкретной модели и модификации кузова, а также проверяют совместимость деталей и обоснованность их списания по результатам кодов диагностики DTC.
* **Экономический эффект:** Ликвидация необоснованных выплат дилерам за «воздушные» нормо-часы и лишний складской инвентарь. Внедрение автоматического блокирующего шлюза на этапе импорта клейма позволяет сократить общие затраты на гарантийный бюджет дилерской сети на **12–15% ежегодно**.

### 🗂️ Архитектура базы данных (СУБД MySQL)

База данных `volvo_antifraud` развернута на движке InnoDB и состоит из трех связанных таблиц:
1. `volvo_cars` — справочник автомобилей. Содержит уникальные 17-значные VIN-коды, даты продажи и жесткую привязку к модельному ряду для контроля платформенной совместимости.
2. `service_orders` — журнал заказ-нарядов. Фиксирует даты открытия/закрытия ремонта, пробег, текстовую жалобу со слов клиента, результаты диагностики (DTC-коды из VIDA), ФИО мастера-консультанта, название ДЦ и подписи VIP-согласований от представительства.
3. `order_details` — спецификация ремонтов. Содержит детальный перечень всех выполненных операций и списанных запчастей с указанием VST-кодов, стоимости и фактически заявленных нормо-часов.

### 💻 Примеры реализованных SQL-скриптов для аудита

#### 1. Скрипт автоматического выявления приписок нормо-часов (VSTG Padding)
Запрос находит сотрудников дилерских центров, которые систематически завышают время выполнения стандартных регламентных работ:
```sql
SELECT 
    o.order_id, o.vin, c.model, o.dealer_name, o.master_name,
    d.sku_or_operation AS vst_code, d.labor_hours AS claimed_hours,
    CASE 
        WHEN d.sku_or_operation = '61414' AND c.model IN ('XC90', 'S80') THEN 0.8
        WHEN d.sku_or_operation = '61414' AND c.model IN ('XC70', 'XC60') THEN 0.9
        WHEN d.sku_or_operation = '43714' AND c.model = 'S40' THEN 5.8
    END AS standard_vstg_hours,
    ROUND(d.labor_hours - (
        CASE 
            WHEN d.sku_or_operation = '61414' AND c.model IN ('XC90', 'S80') THEN 0.8
            WHEN d.sku_or_operation = '61414' AND c.model IN ('XC70', 'XC60') THEN 0.9
            WHEN d.sku_or_operation = '43714' AND c.model = 'S40' THEN 5.8
        END
    ), 2) AS overpaid_hours
FROM volvo_antifraud.order_details d
JOIN volvo_antifraud.service_orders o ON d.order_id = o.order_id
JOIN volvo_antifraud.volvo_cars c ON o.vin = c.vin
WHERE d.item_type = 'Работа'
  AND ((d.sku_or_operation = '61414' AND d.labor_hours > 0.9)
    OR (d.sku_or_operation = '43714' AND c.model = 'S40' AND d.labor_hours > 5.8));
```

#### 2. Скрипт обнаружения несогласованных избыточных запчастей (Part Padding)
Запрос выявляет случаи, когда под визой топ-менеджеров при замене шорт-блока двигателя D5 дилеры скрытно списывали дорогостоящие турбины без каких-либо кодов неисправностей в диагностической карте:
```sql
SELECT 
    o.order_id, o.vin, c.model, o.dealer_name, o.master_name,
    o.approver_signature, d.sku_or_operation AS hidden_part_sku,
    d.item_name, d.cost AS financial_loss_rub
FROM volvo_antifraud.order_details d
JOIN volvo_antifraud.service_orders o ON d.order_id = o.order_id
JOIN volvo_antifraud.volvo_cars c ON o.vin = c.vin
WHERE d.item_type = 'Деталь'
  AND d.sku_or_operation = '31293022' -- Артикул турбины
  AND o.order_id IN (
      SELECT order_id FROM volvo_antifraud.order_details WHERE sku_or_operation = '21005' -- Код замены ДВС
  );
```
